## 1. 用户可获得的结果

独立开启「最近时间线」后，已经进入视口且被 Xs 实际观察到的允许卡片立即进入本机临时列表。
即使只出现 0.5–1 秒、未打开或未达停留门槛，也可在 X 刷新后断网查找刷新前的本地记录。
这不保证覆盖尚未呈现的接口结果、预取、隐藏节点或采样间漏过的瞬时卡片，也不恢复 X 的推荐状态或原虚拟列表。

| 功能 | 写入条件 | 时间与含义 |
| --- | --- | --- |
| 最近时间线 | 独立同意后，允许前台卡片实际入视口且被观察；零停留门槛 | 临时出现记录，不代表阅读 |
| `FEED_VISIBLE` | 现有独立同意、60% 可阅读区域及连续 1.2/3/5 秒门槛 | 合格曝光及实测下界时长 |
| `OPEN_POST` | 现有独立同意及原生确认主动进入详情 | 立即打开历史 |
| 长期保存／`FAVORITE` | 用户明确保存／收藏 | 持久资料；收藏不调用 X 服务 |

本地列表预览不产生 `OPEN_POST`；点开原帖仍按现有原生导航规则判断。
缓冲写入、补正文、重排、批次切换、清理和恢复均不制造 OPEN、FEED、收藏、本人动作或「已读」。

## 2. 默认值与数据边界

- 开关独立、默认 **OFF**；关闭停止新观察，已有内容继续按到期规则清理，另提供「立即清空」。
- 默认保留 **48 小时**；提供 24/48/72 小时、7 天及自定义整数 **1–168 小时**。
- 临时空间是**全应用总预算**，默认 **100 MiB**，可调整数 **25–500 MiB**；不是每个 library 各有一份额度。
- 预算包括临时 SQLite、FTS、WAL/SHM、维护日志及关联暂存/整理文件的实际落盘大小；提交前还须预留写入/整理峰值，不能只按正文 UTF-8 长度报数。
- 先清过期，再淘汰最旧批次引用和无引用正文；仍无法容纳则停止追加，保留浏览可用性。
- 列表显示最早/最近实际覆盖时间、丢弃数及暂停原因；容量不足时不得宣称完整保留48小时。
- 只保存规范 post ID/链接、可见作者/正文、已知发布时间、原生收录时间、来源、批次及观察顺序等元数据。
- 不自动下载图片/视频，不保存 raw API JSON、请求头、Cookie/Token、游标、DM、草稿、隐藏状态或网页自定权限。
- 仅适配经验证的前台顶层时间线路由；后台、锁屏、覆盖层、敏感/未知路由和不明来源停止 admission。
- 缓冲 admission 与 FEED 独立：验证非零实际视口交集、可见样式及遮挡证据；不复用 FEED 的60%门槛，也不降低它。
- 卡片/字段/队列/批次数量必须有界；F1 固定具名上限并测试溢出，F2 保留现有有界 native pull，避免高频全页复制。
- 保存当时可见正文；截断或未知完整性用 LINK_ONLY/PARTIAL，不能因「接口成功」或保存成功升级 COMPLETE。

## 3. 数据不变量与批次

下列是待实现的数据契约，不是现有组件或表名；F1 新临时 DB/索引从独立 schema1 开始，保留 Archive v5 原库，不重建长期资料。
若 F3 晋升身份/新 source 需要长期库字段或枚举，须显式 ADR 修订、版本升级和保留性迁移，并回归备份/导入/合并及旧 APK 升级；不能在 schema5 偷加表或塞未知 source。

1. `library_id`、writer ticket、观察 epoch、document/session/batch 身份与时钟由原生持有；网页只提供不可信候选字段。
2. 每次出现引用包含 post ID、正文版本引用、原生 batch ID、顺序、收录时间及到期依据；正文按内容哈希复用。
3. 同 library、同批次、同 post 幂等；DOM 重绑/刷新正文只补快照或 last-seen，不重排首次位置、不延长该引用寿命。
4. 真实新批次可再次引用同帖；旧引用仍按自身收录时间到期，新引用不令所有历史批次续期。
5. 首次收录时间与可配置 TTL 决定到期；到期边界 `expires_at <= now` 在列表、FTS、批次计数和预览均立即排除。
6. 修改TTL先按旧策略固定已到期集合，只对尚未到期的有效引用重新计算；缩短立即隐藏过期项，延长不能复活已逻辑到期或物理删除的条目；策略版本在实际事务内复验。
7. 持久时间用原生墙钟，进程内计时用单调钟；时钟大幅跳变暂停新入库并提示，F1 测试前跳/回拨，不能延寿至无限。
8. 捕获 provenance、时间线来源和批次原因分别保存；不从 URL `/home` 臆造「正在关注」，未知保持未知或停止不支持页面。
9. 原生刷新/新页面/经验证换流产生新批次；DOM 根替换等推测只能标记 `suspected_refresh`，批次不等于接口响应。
10. 导航中止旧页的新观察；已确认并入队的合法不可变记录不因快速返回而丢失，写入仍受 library/清理代次检查。
11. 账号切换使旧观察上下文失效，不删除资料或隐式切换 library；临时表、查询、删除与晋升都必须隔离 library。
12. 临时数据不自动进入现有元数据/完整备份、合并或统计；其 FTS 与长期搜索分离，避免过期正文仍从 Archive 查到。

## 4. 写入、清理与长期保存

复用现有 `XsLibraryWrites` 的有界 library writer/ticket，不新增可绕过其 epoch 的资料写通道。
临时库事务需串行化全应用配额计量和提交；跨 library 并发不能各自检查后共同超限，锁序与拒绝路径必须有测试。
入队和实际写入都复验 ticket、原生来源、同意状态和缓冲代次；已删除 library 还须在 SQLite 写事务内拒绝。
清缓冲先停相关观察、增加独立 buffer generation，再经共享 writer 顺序屏障删除；不无故作废媒体/其他功能票据。
整库删除先保留既有 durable tombstone，再经既有删除屏障清两库及任务；失败保持待清理，重启不能新建同名空间复活。
日常 TTL/配额维护使用普通共享写序列和当次策略，不把清理当整库删除，不删除长期资料、完成媒体或接收方分享副本。

查询 TTL 与物理 GC 分开：每次查询隐藏过期项；前台/运行中维护及可延迟系统任务回收磁盘。
物理清理要清 FTS/无引用快照、checkpoint/truncate WAL，并在预算允许时整理；峰值整理文件也算预算。
有读锁/空间不足无法回收时展示待回收字节/原因并限制追加，不能把 SQL DELETE 行数当已释放字节。
不用常驻服务或精确闹钟维持清理；强停、休眠与系统调度可延迟物理回收，SQLite/WAL 也不提供安全擦除承诺。

「长期保存」使用现有持久保存语义，「收藏」使用现有本地收藏语义，均须明确用户动作、稳定 promotion ID 和幂等写入。
两库不能假称一个跨 WAL 原子事务：共享 writer 内先验证未过期候选并持久提交 Archive，再确认临时标记；崩溃重试按 promotion ID 去重。
保留原观察时间/来源/质量，另记保存时间；具体 source 映射需扩展并测试现有策略，不能伪造 native detail 或 COMPLETE。
GC 不因待晋升标记永久钉住临时数据；Archive 成功后临时删除/到期不回滚保存，Archive 失败不得显示已保存。
