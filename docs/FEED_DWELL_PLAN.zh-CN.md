# Xs 时间线停留记录｜产品方案与实施规范

当前代码进度以 [本轮实施与验收记录](IMPLEMENTATION_EVIDENCE.zh-CN.md) 为准；下文保留需求基线，待验收项不因源码存在而自动通过。

更新：2026-11-06。状态：用户确认的目标与实现规范，**尚未完成真实 X 时间线自动记录**。对应 [ADR-0004](adr/0004-feed-dwell.md)、[XS-14](IMPLEMENTATION_PLAN.zh-CN.md) 和 [D01–D09](ACCEPTANCE_MATRIX.zh-CN.md)。

## 1. 目标与用户体验

**用户只在 Xs 内刷时间线，看到一条帖子停留了一会儿，哪怕完全没有点开，也可以在本机资料库中找回该帖。** 不强制手动收藏，不创建 X 服务器书签，也不把“出现过”说成“已读”。

- 在 Xs 设置中由用户单独开启「记录时间线停留」。首次默认关闭，不依赖于「打开历史」「收藏到 Xs」或去广告开关。
- 设置档位：**1.2 秒（灵敏）／3 秒（推荐默认）／5 秒（精选）**。最小基线为连续 1200ms，但默认产品模式选择 3000ms；可在设置中随时调整，**只对后续观察生效**，不追改历史。
- 在首页「为你」「正在关注」等经验证支持的时间线上，只要帖子在前台、未遮挡、可阅读区域连续达到可见比例门槛并停留达到所选秒数，即记录一次 `FEED_VISIBLE`。允许同一屏多条同时分别计时，不能只记录屏幕中心那一条。
- 资料库有独立「刷到／停留」时间轴，用户可按日期、**实际有效停留时长**（如 >5s）、关键词、作者、来源、分类及「**从未主动打开**」筛选。无正文显示「仅链接」或「部分正文」，不宣称完整存档。
- 后续点开同帖产生独立 `OPEN_POST`；点击「收藏到 Xs」产生独立 `FAVORITE`。停留记录既不增加 `opened_count`，也不自动加入收藏。
- 退出/切换 X 网页账号仍保留本机资料；站点身份仅作可选来源，资料归 Xs 本机库所有。

## 2. 计时和可见性的准确含义

**计时只表示可见曝光，不是眼球追踪、认真阅读或阅读完成证明。**

- 起点：目标帖子已经真实渲染在用户可见的顶层时间线，Xs 浏览窗口在前台、屏幕解锁、目标资料空间允许该功能，页面不是登录、私信、编辑器、验证、安全页或未知路径；网页预取、未附着 DOM、隐藏卡片均不计。
- 可见率建议基线 60%，实现时以**实际可阅读区域与视口的交集**衡量；对高度大于视口的长帖分段归一化，不能要求整卡同时显示 60% 以上。IntersectionObserver 是候选信号，不是遮罩检测的全部；需补几何/覆盖判定与 Android 前台状态。避免把超小可见块按 100% 误算。
- 采用单调时钟计算连续有效停留（原生 `elapsedRealtime` 或可校正的单调时间源），Unix/墙上时间只用于记录时间轴。应用进入后台/锁屏、弹窗遮挡、页面切走、卡片退出可见区或滚动虚拟列表回收节点时，**结束当前连续区间**；再次出现开始新区间，不把间断时间凑足阈值。
- 3 秒达标后**尽快生成一条合格事件**，即使用户很快划走也不漏。继续停留可更新这条事件的实际有效时长及峰值可见率；异常退场若无法得知末次时长，应记录已确认的最小值和估算/不完整状态，不捏造时长。
- 无交互并不自动等于没有阅读；但不能让屏幕静置导致无限累加。首版可以对单次曝光建立**可配置的上限/不确定标记**，任何上限要有 UI 说明和长文测试，不把超上限区间说成已确认阅读时长。
- 限制观察器维护的活跃节点数、内存、采样频率及本机写入批次；卸载节点立即释放监听，图片/视频异步加载不反复创建曝光事件。
- 页面过滤隐藏了某张推广卡片时，该卡不应再计入曝光；关闭过滤后恢复原页面样式。

## 3. 事件、去重与时间语义

最小目标模型（**不是当前数据库已存在的字段**）：

| 维度 | 设计 |
| --- | --- |
| 资料归属 | `library_id` 由原生生成；不使用正在浏览的 X 用户名充当资料所有者 |
| 帖子实体 | `post_id`、规范 URL；可见作者/正文/发布时间为可空快照 |
| 事件类型 | `FEED_VISIBLE`；与 `OPEN_POST`、`FAVORITE`、`LOCAL_SAVE` 分开 |
| 事件身份 | 本机生成的 `exposure_id`、`document_epoch`、`feed_session_id` 与来源，不接受网页自定资料归属 |
| 时间 | 首次达标的本机墙上时间 `qualified_at_ms`；可选 `started_at_ms`／`ended_at_ms` |
| 时长 | `qualified_dwell_ms` 或 `duration_ms`（单调时钟实测，不能凭贴文发布时间推断），不完整时注明质量 |
| 质量 | `snapshot_quality`（LINK_ONLY/PARTIAL/VISIBLE），是否被遮挡、来源、峰值可见比例的可选证据 |

同一**连续可见区间**只记一条曝光事件，卡片重绘、MutationObserver 回调、同一网页节点反复绑定不额外计次。离开视口后真正再次出现，允许保留新的曝光区间；存储层去重帖子实体，显示层可以聚合「首次／最近停留、合计有效停留、曝光次数」。原有 2 分钟同来源抑制策略只能作为**防短时间抖动的可配置聚合/去重策略**，不得无声抹掉真实、已达标的再次停留；需要明确实现及测例。

搜索「停留超过 5 秒且未点开」以**事件时长条件**配合该资料空间内 **不存在 OPEN_POST** 为准；不要仅凭帖子 ID 或作者判断，也不把一次 1 秒与一次 4 秒间隔相加作为一次 5 秒连续停留。新增时长列采用兼容现有 v2 的保留性迁移，先验证旧 `history_events`、分类、FTS、已下载文件、LOCAL_SAVE 等均保留；没有迁移证据不得更新已有正式用户库。

## 4. 与打开历史、本人行为和收藏分开

| 操作 | 结果 |
| --- | --- |
| 快速划过，无连续达标 | 不记停留 |
| 停 3.4 秒、未点开（默认 3 秒） | 记一条 `FEED_VISIBLE`，`opened_count` 仍为 0 |
| 停 2 秒、选择 5 秒档 | 不记停留 |
| 打开帖子 0.3 秒即返回 | 若打开记录开启且确实进入详情，则立即记 `OPEN_POST`，不需要达到任何停留门槛 |
| 长帖在视口逐段阅读 | 只要实际可阅读区域持续满足条件即可计时，不能因卡片过高永远不达标 |
| 查看别人转帖的帖子 | 可以记录曝光/打开，不等于自己转帖成功 |
| 本人确认转帖成功 | 另记个人行为，来源与真实时间单独保存 |
| 点 Xs 收藏 | 独立 `FAVORITE`，不能触发 X 服务器书签 |
| 登录/退出/切换 X 账号 | 旧观察任务失效，本机资料库不删不隐式切换 |

## 5. 实施技术与验证先后

A. **先在离线合成页面开发** X 专属站点适配器：只观察允许的帖子节点与 SPA 路由，使用 IntersectionObserver + 有界 MutationObserver + 页面/前台状态；原生按需拉取有限事件和可见文本快照，所有数据均当不可信输入校验。

B. 增加 Android 原生控制器：三个独立设置（打开历史、停留记录、显示精简）、档位 1.2/3/5 秒、会话代次与本地资料空间、存储前再校验、稳定 `exposure_id` 去重和有限队列；未知来源默认停止采集，不允许网页删除、导出资料或修改权限。

C. **记录与查询闭环**：含连续停留时长的事件模型、可靠迁移、FTS/分类、按停留时长筛选、未打开筛选、重启/断网查找、返回原帖；记录已停留的可见正文快照，无需用户额外点击收藏。

D. 核验 **真实 X 网页** 的首页/关注流、长帖、视频卡片、混排多帖、引用/转帖、滚动虚拟化、刷新、返回和切换账号；只有真实登录与允许的采集能力验收通过后，才允许相应版本/页面启用该功能。不同 X 布局/语言需单独核验，解析失效则只停增强，不中断原始浏览。

E. 稳定性：长滚动、后台 10 分钟、低内存、异常 JSON、重复节点、进程死亡、清库和旧回调；给出 CPU/内存/电量开销及 SQLite 体积实测。一次成功模拟器演示不等于真机交付。

## 6. 交付优先级与退出标准

- 主线 A 首先交付**打开即记录**，不能被停留计时拖住。
- **XS-14 的“基础停留记录 + 筛选”提前到 B 批次的早期并行开发／验收**，与 XS-07 本地收藏和 XS-08 图片下载共同推进；不再把用户刚提出的核心需求完全拖到 D 批次。
- D 批次保留高级治理：大规模信息流性能、可选精确时长与统计、长期保留/空间配额、异常恢复与兼容性扩大。详细测试见 [D01–D09](ACCEPTANCE_MATRIX.zh-CN.md)。

**首个可验收场景**：默认 3 秒档、用户开启停留记录，正常刷 X 但不打开两条帖子；其中一条连续可见 3.5 秒，另一条 1 秒。随后断网进入 Xs 本地「停留记录」，可以找到前一条及当时可见文字、停留时长与来源，后一条不存在；把第一条加进本地分类后重新找到；继续打开时形成新 `OPEN_POST`，不覆盖停留记录。全部在真实支持版本上测试且隐私边界没有退化。

## 7. 当前进度与边界

仓库已有原生 SQLite/FTS、`FeedCapturePolicy` 最低 1.2 秒策略、`FEED_VISIBLE` 数据事件基础、未启用的网页观察校验和离线测试。本文件提出的 **3 秒默认 UI、可调档位、网页可见性测量、持久时长字段、按停留时长搜索、非打开筛选、真实 X 页面采集** 尚未完整实现。

不要将这个规范文档或历史 CI 通过解释为上述功能已交付。绝不读取 X 密码、Cookie/Token、私信、草稿、后台隐藏内容或任意网络响应，也不通过绕过访问控制获取帖子。
