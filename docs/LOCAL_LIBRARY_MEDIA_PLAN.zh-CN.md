# Xs 本机资料库、下载与分享实施规范

日期：2026-11-06。性质：正式需求与验收基线，**不是已实现报告**。

本文件落实用户的三项决定：可采用自定义许可；点开记录、可选停留、转帖和应用独立收藏；下载图片/视频、管理资源并通过系统分享至其他应用的会话。与旧文档冲突时，产品范围以 ADR-0002 为准。

## 一、用户体验

正常刷 X 是主界面。Xs 原生工具栏提供「收藏到 Xs」「下载」「资料库」，不重复一整套 X 导航。资料库包含历史、收藏、资源、本人内容与统一搜索；分类和标签可跨页面使用。

典型路径：

- 打开帖子即建立历史；稍后凭关键词、作者、日期和分类找回，不需要额外点收藏。
- 点「收藏到 Xs」后选分类，保存可见内容快照。不会在 X 上增加书签、点赞或转帖。
- 帖子有图/视频时点「下载」，明确选择单项或整组；完成后在资源库看预览和来源。
- 在帖子或资源详情点「分享」，选择分享链接、文字、图片或视频文件，调用系统菜单选择目标应用/会话。
- 退出 X 后仍能看本机历史、收藏和已下载资源；仅重新加载原帖需要网络及相应访问权限。

## 二、事件语义

| 类型 | 写入条件 | 时间含义 | 不能冒充的事 |
| --- | --- | --- | --- |
| OPEN_POST | 已授权，主动进入有效帖子详情；不设停留门槛 | 原生打开时间 | 不等于读完；刷新、旋转不算新打开 |
| FEED_VISIBLE | 单独开启，前台可见、无阻挡、连续停留达标 | 满足停留条件的观察时间 | 不等于主动打开或阅读完成 |
| OWN_REPOST | 用户本人转帖操作已确认成功 | 真实成功时间或未知 | 点菜单、失败请求、别人转帖不是本人成功 |
| OWN_QUOTE / ORIGINAL / REPLY | 确认成功或归属确认的导入 | 实际行为/发布时间 | 不保存未发送草稿 |
| FAVORITE | 原生「收藏到 Xs」动作 | 本机收藏时间 | 不更改 X 书签或其他服务器状态 |
| LOCAL_SAVE | 当前版本的链接手动收录 | 本机收录时间 | 不自动变成打开历史 |

点击进入详情后正文尚未加载，可以先存已知 ID/规范链接和 LINK_ONLY；内容到达再更新同一帖子快照。仅点击但导航未生效/无法确认目标，不谎报完整开帖成功。无内容时界面显示仅链接，而不是空白“完整备份”。

同一导航可以有多条更新消息，但只有一个 OPEN_POST。用户离开后重新主动进入同帖，建立新事件。会话代次、文档编号与导航编号均由原生控制；刷新/旋转/进程恢复有显式原因标记。

转帖与引用帖分别保存“执行者线索、来源、原帖、可选引用帖、结果、时间质量”；账号线索不拥有整个本地资料库。撤销转帖更新状态，可保留原始行为轨迹。官方档案中的时间不能不经判断当作转帖时间。

### 时间线停留记录（无需打开帖子）

这项功能已明确为产品目标，完整方案见 [FEED_DWELL_PLAN.zh-CN.md](FEED_DWELL_PLAN.zh-CN.md)。在 Xs 内刷时间线时，用户单独开启“记录停留”，即使**没有点开帖子**，只要帖子可阅读区域连续可见且达到档位，就保存 `FEED_VISIBLE` 与可见内容快照，供后续按时间、关键词、停留时长与「从未打开」查询。

档位为 1.2s（灵敏）、3s（推荐默认）、5s（精选），可见性基线 60%，长帖采用视口可阅读区域的归一化规则。最短 1.2s 仅用于停留，不影响“打开即记”。同一连续曝光一次事件，记录实际有效停留时长；中断不跨段相加，重绘与预取不重复计数。退出网页、遮罩、后台、锁屏、敏感路由暂停；不能宣称眼球关注或已读。基础停留记录**提前至 B 阶段早期**，性能和容量治理留在 D 阶段；现有数据层并不等于网页观察器已经实现。

## 三、资料与账号解耦

默认建立一个 Xs 私有本机资料库，和网页登录分开。收藏、分类、笔记与资产使用 library_id；浏览档案使用 browser_profile_id；本人社交行为可附 actor_hint / actor_provenance。字段是设计建议，最终迁移 DDL 在实现前由测试锁定。

浏览页账号切换会使旧采集任务失效，但不会删除/隐式切走本机收藏。对于不能确认的本人行为，只暂停归属/标记未知，不将全部本机收藏按网站用户名拆散。

旧版本的 account_id 隔离数据全部保留。先建立可追溯的 legacy_scope 映射，再由用户选择合并或继续分开。迁移验证分类外键、事件时间、去重、FTS 和清理，不采用“重建空库”或跨空间静默合并。

## 四、本地收藏和分类

收藏至少保存帖子 ID、规范原帖链接、作者显示线索、可见文本、原帖时间（可空）、本机收藏时间、来源与快照质量。正文按 LINK_ONLY / PARTIAL / DETAIL_VISIBLE 标记；较长不等于永远更正确，正文编辑与补全应有版本/来源规则。

同一帖子可属于多个分类/标签，支持移动、批量分类和备注。首次点击星标成功后立即反馈，分类面板可以随后操作；不要求选分类才能收藏成功。备注只在用户明确选择时进入对外分享。

取消收藏只取消收藏关系；不连带清历史、删媒体或在 X 取消书签。删除某条历史事件不影响收藏；删除一个媒体文件不删除原帖。清全部资料必须给出范围与确认。

## 五、媒体下载与资源管理

### 5.1 发现与选择

只从当前允许观察的帖子内容和已取得的、合法可访问的媒体引用发现候选。原生下载按钮列出图片/视频、可用清晰度、已下载状态。资源解析不是任意 URL 代理或通用网络日志；不抓取登录、私信、隐藏应用状态或全部响应。

图片：单图、图组选择、可用原图质量和实际格式；获取不到原图如实标记，不伪装放大。
视频：先完成可访问的完整文件下载，再依据真实站点数据验证 HLS/DASH。blob 只是运行时对象引用，不能直接当下载地址；播放列表和片段也不能改后缀冒充 MP4。需要可分享的完整输出时明确测试合并、音画同步、时长和格式。不绕过 DRM、付费验证或下载权限限制。

### 5.2 原生任务与落盘

任务状态至少覆盖 QUEUED / RESOLVING / DOWNLOADING / PAUSED / COMPLETED / FAILED / CANCELED。下载只在用户动作或已明确配置的批量动作后启动。采用符合目标 Android 版本的后台任务与通知机制；不通过假音频、无界队列或静默常驻绕过系统调度。

任务参数固定 library_id、资源标识和确认时上下文。每次重定向验证协议/来源；文件名由原生生成，限制类型、数量、体积、时长、重试次数和磁盘容量。禁止任意 file/content、本机/私网探测和危险路径。鉴权上下文只用于经过验证的最小必要请求，不导出 Cookie，不传到任意主机，不把签名链接中的令牌写入普通日志、分享文字或公开报告。

先写临时文件，校验长度/实际 MIME/可播放性，完成后原子登记资产；失败不显示为已完成。续传需服务端支持 Range 及对象一致性校验，否则明确从头重试。取消清理临时片段。通过散列等内容标识去重，但不因同 URL 就假定永远同一文件。

### 5.3 资源库

Asset 与 Post 分开，保留关联。资源项包含本机标识、实际类型、大小、时长/尺寸、下载时间、来源帖子、完整性、保存路径令牌和分类。来源链接失效不删除本地文件；资源已删除时显示状态，不保留虚假可分享入口。

资源页支持图片网格、视频预览、下载进度/失败视图、按时间/类型/来源/分类筛选，批量删除、导出和分享。明确区分“缓存”和“已保存资源”；清缓存不能删用户下载。

默认私有存储，不自动进入公共相册。保存到相册/系统文件是另一个用户动作，并使用合适的系统存储接口。收藏不默认下载整组视频；「收藏并下载」应标明资源数量和预计大小（可获得时）。

## 六、对外分享

目标应用包括微信、QQ、飞书、Telegram，以及系统中支持对应格式的其他应用。不为这些应用编写自动发送、通讯录读取、无障碍操作或账号令牌接口。

分享内容分为：

- 链接：规范原帖 URL，可附用户确认的出处文字。
- 文本：已存文本、作者/出处；截断时明确，不混入私人备注或本机账号信息。
- 单图、多图：实际下载文件，保留原件；图组用兼容的同类 MIME。
- 视频：实际可播放的完整文件；不把 URL 或视频缩略图伪装成视频文件。
- 混合资源：先让用户选择；目标不支持时提供按类型分组或逐项分享，不默认压缩成对方无法识别的内容。

实现方向：ACTION_SEND / ACTION_SEND_MULTIPLE + EXTRA_STREAM + MIME + ClipData + FLAG_GRANT_READ_URI_PERMISSION，通过系统 Sharesheet。FileProvider 或等效受限 provider 仅暴露用户选中的可分享资源，不能暴露根目录、数据库、索引、会话数据、密钥或未完成下载；不授予写权限。

用户选择应用后在目标应用里选择联系人/群组并确认发送。系统 Direct Share 的会话捷径由接收应用提供，Xs 不能保证任意安装版本都有联系人捷径。回调最多说明用户选择了某目标，**不证明已发送或送达**。不把取消或返回当失败后自动重发。

分享授权需覆盖接收方异步读取的合理生命周期，不能打开菜单立即删除临时文件或撤销权限；用受限、可清理的分享副本/租约防“清理资料”和“对方尚在读取”竞态。不得因分享永久开放整个资料空间。

没有 Xs 上传/中转服务器。文件交给其他应用后，该应用会按自己的规则处理/上传；不能宣称对外分享仍永不离开设备。文件过大或 MIME 不匹配时说明原因并提供可理解降级，不默默压缩、改画质或声称发送成功。

## 七、组件拆分与工程复用

现有浏览/数据库不全面重写。计划组件（名称为设计，尚未创建）：

- BrowserHost / ProfileRegistry：参考 ChatGPT Studio 的浏览档案、受控弹窗与页面保留，不复制不适用的认证域名。
- XPageObserver + NativePageController：本地脚本、按需/批量获取、来源/路由/上下文验证；登录/私信/编辑器排除。
- LocalLibraryRepository + CaptureCoordinator：统一保存、导入、收藏、资产与清理，队列有界，代次校验在实际写入前执行。
- FavoriteRepository：独立于 X 书签，与原始帖子/快照关联。
- MediaResolver + DownloadCoordinator + AssetRepository：解析与文件下载分离，任务持久化，完整落盘才提供文件分享。
- ShareCoordinator：统一链接/正文/媒体的预览、授权、系统分享与取消处理。

ChatGPT Studio 的资产台账、下载与加密恢复只作为待逐文件评估的自有代码复用候选；不把尚未审计的全部实现复制进 Xs。最终授权和第三方声明按 LICENSING.md 处理。

## 八、阶段与验收

| 阶段 | 产品交付 | 必须验证 |
| --- | --- | --- |
| A | 正常浏览、自动点开历史、独立资料库边界 | 无停留阈值；刷新不增次数；正文补载不重复；退出 X 不丢资料 |
| B | 早期引入时间线停留基础（XS-14），同步推进收藏按钮、分类、图片下载、资源页、图文系统分享 | 未点开但达标也可找回，默认 3 秒且独立授权；收藏不请求 X 书签；图片真实落盘；目标 App 手动选择会话 |
| C | 本人转帖索引、标准视频下载/分享、精简界面 | 成功行为而非菜单点击；完整视频含音轨；过滤可撤销；不影响登录 |
| D | 已实现的停留记录进一步做性能、容量与统计优化；图组批量、必要的流媒体合并、备份治理 | 长卡片、后台、遮罩、低内存；失败恢复；容量与升级迁移；恢复与分享数据边界 |

针对微信/QQ/飞书/Telegram 分别填写：设备、系统、WebView、目标 App 版本、MIME、大小、单/多文件、是否出现会话、接收方实际可见/可播放、取消、断网、权限、原图/压缩情况。未安装或未测试写 NOT RUN，不写“全支持”。

关键用例：快速点开不足 1.2 秒仍有打开记录；停留未达标无 FEED_VISIBLE；五次重绘只有一次 OPEN_POST；重复收藏无重复关系；切换 X 账号收藏不变；从收藏恢复原帖；收藏后原帖删除仍保留已有快照；取消收藏不删媒体；清缓存不删下载；失败视频不可分享成完整文件；导入/下载/清理并发不会复活旧数据；分享完成/取消不伪造聊天送达状态。
