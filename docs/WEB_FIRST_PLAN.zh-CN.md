# Xs Web-first 完整产品与研发计划

- 文档版本：1.0
- 决策日期：2026-10-29
- 状态：用户已确认 Web-first 方向；本文件为实施与验收基线，不代表已经实现。
- 仓库：ForceMind/Xs；本次规划前核验 main：`56ee934b1a4afe51ac4afc75c4fd6ea2ae8cbe53`。
- 优先级：本计划和 ADR-0001 优先于旧 APK 集成规划。旧方案保留作历史，不继续并行投入。

## 1. 最终定位与成功标准

Xs 是以 X 官方网页为浏览主体、以原生本地资料库为增强层的独立应用。它不修改官方 X 安装包，不运营新的社交网络，不自建账号服务、API 代理或内容服务器。

用户正常使用 X 网页浏览、发帖、回复、转帖及网页版提供的其他能力；Xs 负责记录用户明确同意保存的阅读活动，并提供离线搜索、时间筛选、分类和本人内容管理。不是仅有一个网页窗口的演示程序，也不是把模拟数据宿主称为可用客户端。

成功标准是完整闭环：真实登录 → 正常浏览 → 开启记录 → 主动打开帖子 → 本地检索和分类 → 重启后仍可找到 → 返回原帖。信息流记录和界面过滤在这一闭环通过后分别验收。

## 2. 已确定的决策

| 项目 | 决策 |
| --- | --- |
| 第一交付平台 | Android，复用现有 Java/Android 本地工程 |
| 主要浏览容器 | 系统 Android WebView；是否适用由 W0 实测决定，不提前承诺 |
| 网页增强逻辑 | 独立 TypeScript 模块，构建为随安装包交付的本地 JavaScript |
| 数据存储 | 复用 SQLite/FTS、本地分类与导入；不把历史存进 X 页面自己的 localStorage |
| 原生页面 | 复用并调整现有资料库页面；不因技术路线变化全面重写 UI 或数据库 |
| 首版账号能力 | 一个活动网页会话；多个本地资料空间，不承诺同时登录多个隔离账号 |
| 后续平台 | 先评估桌面浏览器扩展，再按真实需求评估桌面独立窗口与 iOS |
| 网络边界 | X 网页仍正常访问其服务；Xs 新增历史、分类、笔记、索引不上传 |
| 权限边界 | 不要求 Root、无障碍、VPN、证书安装、Cookie 导入或 Token 输入 |
| 规则更新 | 首版随应用版本发布；不下载执行远程脚本 |
| 仓库 | 保持现有公开仓库与独立实现，中英文 README 同步；不新建无必要分支 |

Web-first 是产品路线，不等于所有平台同一套原生代码，也不等于已验证 WebView 登录。

## 3. 必须纠正的技术假设

**浏览器支持不等于 WebView 保证。** X 官方说明支持近期主流浏览器及 WebKit/Chromium 系浏览器，但这不能证明任意嵌入式容器、登录方式或媒体能力都稳定可用。[S1]

**Google 登录必须单独处理。** Google OAuth 政策禁止将授权请求导向开发者可控制的嵌入式用户代理。不能以修改 User-Agent、伪装浏览器或复制 Cookie 来规避。[S2]

**外部浏览器登录不等于内部已登录。** Custom Tabs 使用浏览器状态；WebView 不与普通浏览器自动共享状态。不能把“外部登录后回应用”当作已解决会话交接；没有 X 支持的交接流程时，不导出、搬运或注入会话 Cookie。[S3]

**替换成其他 Chromium 容器不是保证成功的兜底。** 登录政策和可被应用控制的环境这一事实仍存在。正确替代路径是评估真正浏览器中的扩展，而不是不断伪装容器。[S2][S7]

**本地保存不是平台授权。** X 现行条款对未经许可的抓取和绕过技术限制有明确约束。本项目不把“只读 DOM”“没有服务器”或“自用”解释成获得授权；个人使用、公开代码、分发二进制和商店发行分别评估。[S8]

## 5. 产品结构与核心交互

保留 X 网页自己的主要导航，不同时叠两套首页/搜索/通知/私信底栏。Xs 首版只增加窄原生工具栏：当前站点、资料库入口、增强状态与菜单。进入资料库后显示“打开历史 / 刷到记录 / 我的内容 / 分类”，共用一个搜索入口。

首次使用：说明非官方身份和本地数据边界 → 在官方页面完成登录 → 创建或确认本地资料空间 → 选择是否开启打开记录。信息流记录、正文快照和界面过滤均独立说明，不用一个“同意全部”按钮替代。

主要操作：
- 资料库可以按关键词、作者、类别、行为类型和时间依据组合筛选；默认按本地打开时间排序。
- 单条记录支持返回原帖、分类、手动保存、删除本地记录；删除不会修改 X 上的帖子。
- 分类以原生面板为主。首版不依赖在每条 X 帖子操作栏里插入按钮；后续验证 DOM 稳定性后再增强。
- 正文缺失或被截断时如实显示“仅链接”“部分正文”；不能把快照叫完整永久备份。
- 适配异常时显示“增强已暂停，正常浏览不受影响”；恢复原网页样式，不妨碍登录、发帖或返回。

目标最小路径：找回内容不超过“打开资料库 → 搜索或日期筛选 → 打开结果”三步。这是设计目标，不是现有实测结果。

## 6. 架构与信任边界

```text
X 官方网页（远程、不可信输入）
        ↓ 只观察经许可的帖子节点与导航
Xs Web Enhancer（本地打包脚本、独立功能开关）
        ↓ 有上限的结构化观察消息
Origin / Frame / Route / Session / Schema Gate
        ↓ 原生补充资料空间、会话代次、接收时间
Capture Controller → 有界串行队列 → 现有 SQLite / FTS
        ↑
原生资料库：搜索、分类、设置、导入、删除、备份
```

网页不能直接操作 SQLite。所有 SQL、文件操作、资料空间选择和权限变更由原生代码控制。网页收到的回应仅为最小确认结果，不能查询整库、读取其他账号、导出文件或改变记录开关。

拟新增模块：`app-android/`（正式浏览容器）、`web-enhancer/`（观察与样式增强）、`contracts/`（消息与导出格式）、`tests/web-fixtures/`（合成/脱敏页面）、`compat/web/`（版本、能力、语言与验收矩阵）。这些路径是规划，不代表当前已经创建实现。

保留现有 `src/main/java`、`src/android/java`、`xs-runtime`。初期不为了目录漂亮进行大规模搬迁，不无故迁移 ORM、搜索引擎或编程语言。

## 7. W0：登录与核心网页能力验证

先做没有抓取脚本、没有资料库桥接的最小浏览容器，用测试账号验证：

| 验证项 | 要记录的证据 |
| --- | --- |
| X 账号直接登录 | 真实流程、是否进入主页、是否出现限制；不记录密码和验证码 |
| 两步验证与会话恢复 | 退出应用、进程终止、重启、会话过期后的真实表现 |
| Google/Apple/Passkey 等方式 | 单独登记支持/不支持/未验证，不从一种成功推断全部成功 |
| 浏览与互动 | 主页、详情、搜索、个人页、发帖、回复、转帖；测试账号人工操作 |
| 上传与媒体 | 系统文件选择、图片上传、视频播放/全屏、返回与下载权限边界 |
| 账号退出/切换 | 是否可识别页面状态变化、是否及时停止增强 |
| 消息等其他网页功能 | 单独兼容性记录；Xs 不观察、保存或修改私信内容 |
| 生命周期 | 旋转、锁屏、后台、渲染进程崩溃、弱网和断网 |

每次记录设备、系统、WebView 提供者及版本、应用提交、测试日期、语言和步骤。目标包含 Android 16 真机；旧系统支持范围由兼容性结果决定，而不是仅凭 minSdk。

W0 三种结论：
1. **通过**：目标用户实际需要的登录方式与核心浏览可用，进入 Android 路线。
2. **有条件通过**：如直接登录可用但社交登录不可用，明确限制后仅发布对应范围测试版。
3. **不通过**：停止 Android 套壳扩张，复用增强逻辑评估桌面浏览器扩展；浏览器兼容模式只能用于正常浏览和手动保存，不能宣称自动采集或去广告仍工作。

W0 不通过不意味着已完成主产品。没有真实账号流程证据，不发布“登录已支持”的结论。

## 8. 帖子主动打开记录

打开记录必须同时满足：用户有明确打开动作、帖子详情路由生效、目标帖子真实呈现、原生应用在前台、用户已开启记录、当前资料空间和会话状态有效。

同一次导航产生多个渲染/路由回调只记录一次；用户离开后再次主动进入同一帖则保留新事件。刷新、屏幕旋转、进程恢复旧页面、时间线预取、回复卡片渲染不伪造新打开。点击图片、引用卡片和回复的语义用测试明确，不从“URL 包含 status”一项就断定用户阅读。

字段包括帖子 ID、规范链接、可见正文、作者、原帖发布时间（可空）、原生观察时间、来源和解析质量。仅取已经显示的必要内容；不读取隐藏 React 状态，不包装 fetch/XHR，不抓取任意响应，不自动滚动加载，也不自动展开被截断的正文。

事件与帖子内容分开：一次新打开增加事件，不重复创建同一资料空间内的帖子实体；后续截断文本不能覆盖先前更完整的快照。引用与被引用帖子不能混淆作者和时间。

## 9. 信息流“刷到”记录

保持独立开关、独立事件和独立时间字段。默认关闭，开启前说明记录范围、保留期及空间限制。

基线条件：帖子满足至少 60% 的约定可见比例、连续停留至少 1200ms、页面可见、应用在前台且窗口有效、帖子没有被 Xs 隐藏。滚出、后台、锁屏、原生资料库覆盖、已识别遮罩或账号状态变化立即取消计时。同一资料空间、帖子和来源 2 分钟内重复曝光抑制，不影响主动打开记录。

IntersectionObserver 主要反映相交关系，不能单独证明内容真正被看到；需结合 Page Visibility、原生生命周期和可用的遮挡判断。不能把这项指标称为眼动或注意力检测。[S6]

长帖超过视口而永远达不到原比例时，首版宁可不自动记录；后续若改用“可测量阅读区域”必须新增协议版本和测试，不能悄悄改变 60% 的含义。无法确认可见性时停止该条采集，不猜测用户看到了。

## 10. 我的帖子、回复、引用与转帖

第一条可靠路径继续是用户主动导入官方数据档案，并确认归属。导入不会形成阅读历史，也不代表文件涵盖账号全部行为。

网页只提供“观察到的状态”。看到转帖标记不等于刚执行了一次转帖；原帖发布时间不等于转帖操作时间；点击按钮不等于服务端操作成功。不能确认的行为时间保持 NULL，并标注“时间未知”或“首次观察时间”。

首版承诺范围：整理已经导入、手动保存或可靠观察到的本人内容，不承诺自动拉取全部历史，不承诺恢复删除、撤回或从未保存的内容。原创/回复/引用/转帖的判断保留来源与置信度；账号归属不明时不进入“已确认我的内容”。

多分段/ZIP 导入为后续任务：流式处理、归属元数据、压缩炸弹与路径穿越防护、取消恢复、重复导入幂等。现有 16 MiB 单分段上限在实现前保持不变。

## 11. 本地资料空间、账号与会话

现有 `bindAuthenticatedAccount` 的契约要求可信稳定账号 ID，禁止把帖子作者、页面昵称或 @用户名当作认证结果。Web-first 不得将一个随机本地 UUID 伪装为这个认证 ID，也不得直接放宽旧方法后继续宣称强账号隔离。

新增明确语义：`browserProfileId` 表示浏览会话容器；`archiveScopeId` 是原生创建的本地资料空间；`accountBinding` 记录用户确认的账号显示信息、来源及可信程度。用户确认是用于组织本地资料，不等于 X 签发的身份验证。

首版只允许一个活动网页会话。进入登录、退出、账号菜单切换、原生资料空间切换、上下文不一致时，立即暂停采集，提升 `sessionEpoch`，丢弃旧代次待处理消息，再要求确认。不能可靠检测账号切换时，不开启自动归属模式；仍可手动保存到明确选定的本地空间。

资料空间由原生决定，页面消息不得自选 scope/account。不同空间的搜索、分类、导入、清理均带独立作用域。未来真正多账号功能必须证明 Cookie、WebStorage、缓存和工作线程同样隔离，不能仅创建两个 WebView 就标成完成。

数据库迁移为保留性迁移：新增 scope/profile 元数据与来源字段，映射旧 account_id；不擅自重命名、合并或丢弃旧用户数据。具体 DDL 和版本号在迁移实现前由测试固定。

## 12. 网页到原生的最小桥接协议

采用运行时能力检测的 origin-scoped message API；Android 优先 `WebViewCompat.addWebMessageListener`，校验回调真实 `sourceOrigin` 和 `isMainFrame`。不支持所需安全能力时关闭自动增强，不退回对任意页面暴露的通用 Java 接口。[S4][S5]

第一版消息类型限于能力报告、导航观察、帖子快照、可见性候选及非敏感诊断码。字段使用固定 schema；协议版本、消息类型、帖子 ID、URL、文本长度、时间类型、数值范围均验证。不得提供执行 SQL、读写路径、启动任意 Intent、导出历史、删除资料、启用记录或获取 Cookie 的接口。

初始工程预算（待压力测试校准）：单消息编码后不超过 64 KiB，正文上限沿用核心 16,000 字符约束，正常速率每秒最多 20 条、短时突发 40 条，队列最多 128 条。越界拒收；持续异常暂停增强并展示本地状态，不能无限排队、崩溃或悄悄覆盖旧记录。

原生补充可信的资料空间、会话代次和接收时间；连续停留采用单调时钟计算，展示时间保留墙钟及质量标志。文档代次、序列号、导航 ID 防旧页面重放和重复，但不是身份认证。

特别注意：origin 只证明消息来自哪个站点，不证明消息来自我们的脚本。同源其他脚本可能调用桥；因此所有输入仍不可信，桥只接受有限观察消息，不向页面返回私有资料。若使用隔离执行环境，必须对目标 WebView 的实际能力测试，不能假设它天然等价于扩展隔离世界。[S4][S7]

## 13. 网页适配与清爽界面

网页解析按能力拆分：路由、帖子正文、作者、发布时间、账号上下文、广告标记、推荐模块、订阅入口。每项独立启停；一个选择器失败不应拖垮所有功能。

优先使用经实测的结构和语义标记，不依赖随机 CSS 类名或只匹配英文的文本。覆盖简体中文/英文、深浅色、移动窄屏、图片/视频、引用/回复、长帖、已删除和受限状态。未知结构不抓取、不误归属。

界面过滤分开设置：推广帖子、会员营销、冗余推荐。首个验证版全部默认关闭；仅启用经过回归的规则。不隐藏安全警告、验证码、隐私同意、登录表单或用户主动进入的付费页面；不解锁 Premium 权益。

先用可撤销 CSS/节点标记，避免破坏 React 管理的结构；必要时保留布局占位，防止滚动位置跳变。误判时恢复原样，一键进入无增强模式。隐藏仅是显示层行为，不代表不再请求广告资源或 X 不再记录访问。

观察器只扫描新增/变化的帖子区域，节流并释放失效节点；不每帧扫描整个页面。规则随签名应用版本交付，测试夹具使用合成或经授权脱敏内容，不把真实私信、登录页面内容或个人浏览历史提交公开仓库。

## 14. 安全与隐私实施要求

### 14.1 导航与页面权限

仅对明确的 HTTPS X 顶层来源启用增强；精确解析 scheme、host、port，禁止字符串包含判断和任意通配。旧域名跳转不自动获得桥接权限。外链、t.co 跳转、下载与新窗口分别处理，最终站点不可信时交外部浏览器。

这里限制的是桥接来源与顶层导航，不是粗暴封禁 X 所需的全部图片/视频/CDN 请求。正常子资源不因此获得原生权限。

证书错误拒绝继续；禁用明文传输与不需要的 file/content 访问，不允许网页请求任意本地文件。生产构建关闭 WebView 调试。不自动授予相机、麦克风、定位或通知；仅在明确功能、来源与系统权限流程下按最小范围授权。[S5]

### 14.2 登录与敏感路由

登录、验证、安全设置、私信和编辑框不做内容提取。原生端对这些上下文拒收采集；SPA 页面切换同样处理，不能只检查首次加载 URL。未知路由默认不采集。

“不采集凭证”指 Xs 不自行读取、复制、上传、导出或记录凭证；正常网页登录必然由 WebView 管理会话 Cookie，不能宣传成设备完全不存 Cookie。Xs 的宿主代码技术上有较高权限，用户仍需信任可审查的源码、依赖与签名构建。

### 14.3 本地保护与网络说明

归档保存在应用私有目录；不宣称现有 SQLite 已加密。搜索明文索引、WAL、缓存、日志和备份都纳入威胁模型。W4 对静态加密方案独立立项、基准测试与迁移验收，未实现前明确显示保护边界；系统锁屏不等于应用独立加密。

排除敏感数据的云备份和设备迁移，配置并验证不同 Android 版本规则；不能只写 `allowBackup=false` 就断言所有设备迁移均被禁用。[S9]

没有 Xs 服务器、分析 SDK 或后台同步。X 网页自身仍会向 X 及其服务依赖发请求；Xs 不是匿名工具，也不能保证 X 无法得知用户使用方式。

## 15. 导出、清理、留存与恢复

本地记录不是云备份。卸载、清数据或设备损坏可能丢失，首启和设置中应明确说明。

资料导出只包含本地归档，不含浏览器会话、Cookie、Token 或私信。提供版本化可移植格式，包含 posts/events/actions/categories/notes、记录数和完整性校验；校验和不是加密。加密备份采用成熟库与经评审的口令派生和认证加密，不自制算法，不将仅绑定当前设备的密钥当作跨设备恢复方案。

明文导出需二次确认，系统文件选择器由原生发起。恢复到暂存库，先验证版本、大小、条数、scope 冲突及完整性，再事务合并；失败不覆盖现有库。

默认不自动删除用户分类、手动保存、本人导入内容及主动历史。信息流可建议 90 天保留，但必须在开启时明确并由用户确认。设置可查看各类占用；达到用户设置上限时暂停自动采集，而不是静默删除重要数据。首版不自动下载图片和视频，保存文本、链接与必要元数据。

“清除资料”与“退出 X/清除网页会话”是不同操作。清除资料需先停采集、推进 epoch、处理队列，再在事务中清 posts/events/actions/categories/FTS 等相关数据；防止旧队列在清空后写回。锁定、取消、崩溃与账号切换均需测试。

删除对应用逻辑生效，不承诺闪存、系统副本或用户导出的文件可被取证级永久擦除。

## 18. 测试与验收矩阵

自动化层次：现有 JVM/SQLite 回归；合成 DOM 单元测试；真实浏览器执行合成页面；Android WebView 仪器测试；测试账号的人工真机验收。浏览器自动化通过不代表 WebView 和 X 真实会话通过。

必须覆盖：
- 首次登录、不同登录方式、两步验证、会话过期、退出、切换、进程重建。
- 主动进入一次记一次；刷新/旋转/DOM 重绑不加次数；再次主动进入新增。
- 59%/1199ms 不记；连续 60%/1200ms 的受控夹具记一次；后台/遮罩取消；来源去重不影响主动打开。
- 未确认资料空间、过期 epoch、旧页面消息、跨来源/iframe、伪造 scope、过大/畸形 JSON、消息洪泛、SQL/HTML 注入。
- X 登录/验证码/私信/草稿输入内容不进入数据库、日志、测试截图或错误报告。
- 分类、导入、清理、恢复期间切换资料空间；清空后旧消息不能复活；重复导入不重复事件。
- WebView 渲染进程终止、存储满、数据库升级失败、低内存、断网、系统返回、上传取消、无障碍字号。
- 中文/英文、暗色/亮色、不同字体比例、长帖、引用、图片/视频、删除或受限帖子。
- 过滤开关关闭恢复原页面；误过滤无安全警告丢失；规则失效只停相关功能。
- 归档备份排除浏览会话；升级保留用户数据；清除会话不暗中删除归档。

发布阻断级：凭证/私信泄漏，跨空间读取或写入，任意文件/SQL/Intent 桥接，数据不可恢复丢失，清理后旧消息写回，无法关闭的页面破坏。任何一项未解决均不得标记正式版。

## 19. 性能预算与维护策略

下面是待验证目标，不是现有成绩：以 50,000 帖、200,000 事件的合成库测试，FTS 类查询 P95 目标 300ms 内，中文子串复杂筛选 P95 目标 800ms 内，本地资料库首屏目标 800ms 内。记录测试机、冷热缓存、查询分布、WebView 版本和构建模式；不把网络页面加载时间归到本地搜索指标。

SQLite 写入不占 UI 主线程，有界队列；采集脚本不主动发额外内容请求、不全页高频轮询；连续滚动/切后台后不持续增长观察器与内存。背景状态关闭计时和新增采集，网页自身网络行为单独观察。

每个发布版保存 appVersion、Git SHA、WebView 范围、adapterVersion、协议版本、数据库版本、语言/主题测试结果、已知不支持项。网页无法像 APK 一样固定服务器版本，故用能力探测、精确失败状态和可撤销规则，而不是假设旧签名 allowlist 可以解决。

## 20. 跨平台与通知边界

桌面优先评估标准浏览器扩展：在真实浏览器中保留正常登录环境，增强脚本在扩展隔离上下文运行，本地资料存扩展私有存储。复用 TypeScript 观察器、消息规范、测试夹具和导出格式，不声称原生 Android SQLite/UI 无修改即可复用。[S7]

桌面独立窗口以后再做容器 ADR；不能因追求统一框架同时引入 Rust、Electron、Flutter 多套栈。iOS 以后独立评估 WKWebView/扩展等方案、登录与分发；Apple 4.2 最低功能和 5.2.2 第三方服务许可要求分别是发布约束，不因原生资料库存在就保证审核通过。[S10]

首版不承诺官方客户端同等推送、后台接收、通话或其他网页版未验证功能。不通过常驻后台、高频轮询或读取通知内容补齐。通知若进入后续范围，必须另设不上传私信/凭证的方案和真实后台测试。

## 21. 风险与停止条件

| 风险 | 处理 | 停止/降级条件 |
| --- | --- | --- |
| 登录或安全挑战不支持容器 | W0 前置验证 | 不绕过；转真实浏览器扩展评估 |
| DOM 更新、实验分流 | 能力拆分、夹具回归、原页面恢复 | 无法确认结构时停止相应增强 |
| 网页身份不可靠 | 本地空间与可信认证分离 | 无法判断切换则停自动归属 |
| 同源消息伪造 | 只写观察、无资料读取、原生控制权限 | 持续异常暂停桥接 |
| 平台条款或商店许可不明确 | 发行前独立审查和必要许可 | 不把通过技术测试当公开发行批准 |
| 本地资料丢失/泄漏 | 备份、迁移、最小日志、保护边界 | 发布阻断项未修复不发布 |
| 维护范围失控 | Android 有条件主线，其他平台分阶段 | 不同时开四个平台和自研浏览器内核 |

X 的条款页面当前标注生效日为 2026-10-09，明确存在抓取及技术限制约束；具体功能的适用性需按场景审查，不能据此保证不封号或保证违法。账号风险、法律判断和技术安全是不同问题。[S8]
