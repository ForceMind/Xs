# Xs · 更纯粹、更好用的 X

[简体中文](README.md) | [English](README.en.md)

**Xs 是独立研发的 Android 本地增强工程。** 它面向现有 X（原 Twitter）客户端，不重做社交网络，也不建设新的账号、信息流或后端服务。

我们希望保留 X 熟悉的浏览、发帖、回复、转帖、私信和通知体验，同时让用户能够更高效地使用和整理内容。

> 项目处于早期研发阶段。目前提供本地历史索引核心、Android 存储层、原生归档页面和测试；**尚未提供可安装的 X 增强版 APK**，尚未完成 X 客户端注入与实机验证。

## 目标功能

| 能力 | 具体体验 | 当前状态 |
| --- | --- | --- |
| 界面精简 | 隐藏广告、冗余推荐及不必要的订阅提示 | 设计中，尚未接入 |
| 浏览历史 | 主动打开帖子形成独立事件，显示每次访问时间 | 数据与原生页面已实现；X 端接入待完成 |
| 信息流快照 | 独立开关，实际看见并停留至少 1.2 秒才记录；去重与来源分类 | 本地策略与数据层已实现；X 端可视事件接入待完成 |
| 时间轴 | 按阅读时间回看打开过的帖子 | 数据层及原生页面已实现；客户端入口待接入 |
| 本地搜索 | 中英文关键词、账号、分类、个人行为与五种时间依据，80 条分页加载 | 数据与原生页面已实现；X 客户端入口待接入 |
| 个人帖子管理 | 按原创、回复、引用、转帖管理自己的内容 | 数据模型已预留；客户端事件接入待完成 |
| 文件夹与分类 | 自定义分类并整理帖子，离线保存 | 数据层及原生页面已实现；客户端入口待接入 |
| 多账号隔离 | 不同 X 账号使用独立本地索引 | 数据层已实现；端侧验证待完成 |

## 产品原则

- **依托现有 X 客户端**：不把 Xs 做成另一套独立社交客户端。
- **本地优先**：新增阅读记录、分类和搜索索引留在设备上。
- **明确记录语义**：“主动打开历史”和“实际浏览的信息流”是两套事件；后者独立选择开启，且需要前台可见时间达标，预取绝不记录。
- **时间准确**：区分帖子发布时间、转帖操作时间、本地阅读时间与刷到时间；未知数据不伪造。
- **隐私优先**：默认不录制；不收集登录令牌、密码、私信或任意网络响应。
- **独立实现**：Xs 维护自己的数据模型、存储、界面和版本适配代码。

## 工程结构

```text
xs-runtime/           Android Library 工程（原生归档界面与存储）
dev-harness/           仅开发验证的离线模拟数据宿主（并非 X）
src/main/java/        不依赖 Android 的链接识别、查询与 Schema
src/android/java/     Android SQLite、事件桥接与 UI
tests/                JVM + SQLite 校验
scripts/              测试脚本
docs/                 需求、架构和里程碑
.github/workflows/    持续集成
```

## 验证本地核心

需要 JDK 17+ 与 Python 3：

```bash
git clone https://github.com/ForceMind/Xs.git
cd Xs
bash scripts/test-core.sh
# 需要 Android SDK、JDK 17 和 Gradle 8.9 时，可以构建离线开发测试宿主：
gradle :xs-runtime:assembleDebug :dev-harness:assembleDebug
```

Android 模块构建说明见 [架构文档](docs/architecture.md)。其中 `xs-runtime` 产出 AAR；`dev-harness` 产出**仅供开发验证的模拟数据 APK**，并不是经过修改的 X 客户端。两者都不能替代真实的 X 集成验收。
