# Xs · 更纯粹、更好用的 X

[简体中文](README.md) | [English](README.en.md)

**Xs 是独立研发、本地优先的 X 使用增强工程。** 用官方 X 网页正常浏览和社交，用应用自己的本机资料库记录打开历史、收藏分类、管理本人内容、下载图片/视频，并把选中的资源分享给其他应用。不修改官方 X APK，不建设新的社交后台或账号代理。

> **当前是内部开发 PoC，不是正式客户端。** 在既有打开/停留、收藏与图片分享基础上，新增 v4 本人行为/撤销索引、窄范围标准 MP4 下载与分享、可撤销精简夹具、元数据备份恢复和显式资料空间合并。真实 X 自动采集、现场行为确认和网页精简仍关闭；[CI 42357220689](https://github.com/ForceMind/Xs/actions/runs/42357220689) 的 core、构建及 API 30/36 均通过，合成仪器共 **146 项**（每 API 为 36 项宿主＋37 项客户端，零失败/错误/跳过），真实登录、X 媒体来源及接收应用仍需单独验收。

本轮源码范围、限制与实际 CI 见 [阶段 C 与资料治理证据](docs/ROUND_C_EVIDENCE.zh-CN.md)；此前离线历史/停留/图片分享结果保留在 [既有研发执行记录](docs/IMPLEMENTATION_EVIDENCE.zh-CN.md)。

当前验证源码为 `4ee242e`，933 条 JVM 断言及 SQLite/观察/精简 DOM 回归通过。客户端和运行库 Lint 各 0 Error / 0 NewApi / 11 Warning；API 26/27 实际运行仍 NOT RUN。备份恢复与合并的数据库/事务回归已通过，SAF 文件选择器及新增备份/合并 UI 未专门自动化，真机仍 NOT RUN。详见 [CI 摘要](docs/evidence/round-c-ci64.json)。

CI 调试证书可能每个 job 不同，不保证覆盖旧 PoC 升级。有数据的旧 Xs 不要为换装直接卸载；当前备份只含元数据，不含媒体。优先使用空白或隔离测试环境，稳定签名仍待完成。

## 用户确认的体验

**点开即记，刷到停留也可找回。** 用户开启打开历史后，在 Xs 主动进入有效帖子详情就记录，不设停留门槛、不要求额外保存。未点开的时间线帖子也可以由用户**单独开启停留记录**：可选 **1.2秒/3秒（推荐默认）/5秒** 连续可见阈值，达标后本地留存实际停留时间与可见快照，可筛选“停留超过5秒、从未打开”；不把曝光说成已读。刷新、旋转、正文补载不虚增打开。本人转帖只在确认成功后记录。

**收藏属于 Xs。** 提供「收藏到 Xs」按钮、分类、标签和备注，不替用户调用 X 书签、点赞或转帖。退出/切换 X 账号不删除或隐式切走历史、收藏和资源。浏览 Profile、应用资料库、本人行为执行者是不同概念。

**下载进入资源库。** 用户选择图片、图组或视频下载，完成后可本地预览、查看来源、按时间/类别管理、重试、取消、导出或删除。收藏不默认下载全部媒体；缓存不等于用户下载，清缓存不能删主动保存的文件。

**分享真实文件。** 选链接、正文、单图、多图或视频，通过系统分享菜单选择微信、QQ、飞书、Telegram 等支持对应内容的已安装应用，再选会话并确认发送。联系人捷径由接收应用提供，不读取聊天令牌或自动发送；调起菜单不等于送达。

| 手动帖子链接保存、其他 App 分享到 Xs | 已有；只是链接，不等于正文快照或自动历史 |
| tweets.js / tweet.js 导入 | 单文件/分段上限 16 MiB；用户确认归属，不据此验证网页登录或推断执行者；含糊 RT 文本保留快照但不冒充转帖 |
| 原生主动获取 + 本地打包观察器 | 已实现有限读取、严格 JSON、代次/队列校验；只在离线夹具接入，真实 X 自动采集关闭 |

| 本人行为记录 | 原生操作身份与成功确认、四种类型、撤销轨迹和档案来源已实现离线闭环；现场适配仍关闭，未知执行者/时间/当前状态不补假值 |
| 独立收藏按钮、标签、备注、分类 | 已实现；真实浏览器收藏先存链接，本地已有正文可保存快照；不调用 X 书签 |
| 图片任务、资源库、文件分享 | 已实现窄范围图片选择/下载校验/预览/分类/导出/多图分享；中断后从来源重新选择，实际 X 与接收应用未验收 |
| 视频下载与分享 | 已有显式选择直链标准 MP4、校验后入库/预览/分享源码；仅 H.264、可选 AAC、≤100 MiB/10分钟；合成下载/解码/Provider回归通过，实际 X/接收应用未验收 |
| 广告/会员营销/推荐精简 | 三个默认关闭的独立开关、可恢复规则与生命周期控制已接合成夹具；真实浏览器未接入，不能据此启用真实 X |
| 元数据备份恢复与空间合并 | 明文备份≤16 MiB/20,000条，schema 3→4恢复到新库；显式选择2～4库合并到新库，≤8 MiB/20,000条；源库保留，不含媒体文件/下载任务/网页登录状态 |

标准视频检查包含 MP4 容器/样本范围、完整下载长度、轨道与时长核对，以及首尾视频帧和可选 AAC 音轨的有限解码；不等于逐帧播放或接收应用验收。blob、HLS/DASH、分片、加密或未知格式会拒绝，不导出浏览器会话来补取资源。中断后明确从来源重新选择下载，不宣称断点续传或可靠后台调度。

备份经系统文件选择器交给用户选择的文档应用，文件为明文，校验和仅检测损坏，不证明作者/账号身份；恢复不会建立原生行为确认权限。合并使用用户预览时的元数据快照，普通后续编辑需重新预览才能加入；来源被清理或代次失效时拒绝提交。同一旧行为身份的来源冲突会拒绝合并；结果对话框仅允许撤销刚创建、元数据未修改且无媒体/下载任务的新库；已修改或含媒体时拒绝，保留现有任务与源/默认库。两种操作都不搬运媒体文件。

## 实施方向

参考已有 ChatGPT Studio 的 Android 浏览生命周期、Profile、受控窗口和原生主动获取模式；保留 Xs 的 SQLite/FTS 与 UI，为 X 单独实现本地打包的帖子观察脚本。优先用原生主动取回受限结果完成历史，不把通用双向桥作为第一版前提。返回值仍不可信，实际写入前必须校验上下文、授权、代次和导航身份。

离线观察器、迁移、收藏与媒体开发可和真机验证并行；未验证的真实站点采集不能默认开启。历史方案中的「等 W0 后才开始所有开发」不作为当前执行方式。

交付顺序：**A 浏览与点开自动历史 → B 早期停留记录（无需点开）＋收藏、图片、资源页及分享 → C 本人转帖、视频与精简 → D 长期停留性能、容量及发布加固。**

## 当前可测试的手动流程

浏览器菜单可收藏当前帖子链接、显式选择帖子图片或支持的直链 MP4，并打开资源库；资源库可预览/导出/系统分享完成文件。资料库提供打开、停留、收藏、本人内容索引、离线搜索，以及「备份 / 恢复」和资料空间选择中的显式合并。其他 App 分享到 Xs 仍是链接补充路径，重复保存不制造阅读历史。真实网页没有合格直链时应提示不可下载，不把播放中的 blob 当作成品。

## 隐私、迁移与删除

打开历史、停留与过滤分别授权；不读取密码、验证码、Cookie/Token、私信、草稿或隐藏状态。X 网页仍正常联网，Xs 不自建资料上传服务。用户主动交给其他 App 的文件随后按接收方规则处理，不能再承诺永不离开设备。

取消收藏、清历史、删资源、清缓存、退出 X 和删整库分开处理。旧 account_id 数据保留映射，不静默合并、不重建空库；并发导入/下载/分享/清理不能使旧内容复活。既有 SQLite 不宣称已加密，网页无整库读取、任意 SQL、导出或删除权限。
